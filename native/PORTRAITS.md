# キャラ画像の割当

通常キャンペーンの上部「キャラ画像」から対象キャラと画像ファイルを選択します。
キャラクリエイトではなく、表示画像だけを変更します。能力・装備・ゲーム進行は変わりません。
対象は編成外も含む11人です。同職業・同名でもキャラIDで区別します。
「解除して元画像へ」で配布画像へ戻ります。「進行を保存」で割当も保存します。
旧セーブの読込・新しく始めるでは元画像に戻ります。
戦闘／木人ウィンドウを開いている間は、先にその画面を閉じてから設定します。

## 画像と保存

- 対応: PNG、JPEG、WebP、BMP、GIF。アニメーションは先頭フレームのみ。
- 通常ファイルのみ。URL取得・SVG・スクリプト等は非対応。
- 入力上限16MiB、各辺8192px、1600万画素。破損ファイルは割当前に拒否。
- EXIF方向を反映し、透過と縦横比を保持して最大256×256pxのPNGへ縮小。
  メタデータを除去したコピーを `native/user-data/portraits/<SHA-256>.png` へ原子的に保存。
  元ファイルは変更しません。フル解像度の原本は保持しません。
- 表示は48×48px以内に収め、トリミングや縦横比の引き伸ばしをしません。
- 店の「買い替える仲間」の選択名の上、配置、戦闘、木人で共通のキャラID解決。
  敵や同じ職業の別キャラへ勝手に適用しません。
- 進行JSONのトップレベル `nativePortraits` にバージョン1・ID別SHA-256・PNGの
  Base64を保存。元パスを記録しないため、元画像や内部コピーが消えてもセーブから復元可能。
  通常の8MiBセーブ読込上限内に収まるよう、1画像300,000バイト以下。
- Python側が画像部分を検証して除き、既存JSエンジンへ元の進行形式を渡します。
  画像またはゲーム状態の読込に失敗した場合、現在の割当と進行は変更しません。
  旧セーブは画像指定なしとして互換。ゲーム状態のバージョンは変更しません。
- 解除時に内部PNGは削除しません。別の古いセーブの画像を破壊しないためです。
  内部コピーはGit対象外です。実行フォルダの書込権限が必要です。

## 追加依存

画像のデコード・EXIF補正・透過縮小のため **Pillow 12.3系** を使います。
`python -m pip install -r native/requirements-portraits.txt`（ゲームを動かすPythonを指定）。
この作業でインストールは行っていません。検証環境にはPillow 12.3.0が既存でした。
Pillowがなくても通常起動・既存画像・旧セーブは動作します。
画像の取込、カスタム画像入りセーブの読込にはPillowが必要で、不足時は画面に理由を表示します。

## 統合向け

`portraits.resolve_portrait(images, member)` → Tk画像またはNone。
`PortraitImages` はdict派生で、配布画像辞書とID別割当を分離しています。
既存 `images=` 引数の共有をそのまま使用します。Appの引数追加やJS変更はありません。
通常dictでも元の画像解決にフォールバックします。
装備担当は `render_shop` のselectorフレーム内portraitを、戦闘演出担当は
`App.draw` の共通resolver呼出を残してください。
キャラ画像ダイアログは独立しており、仲間・装備UIの全面変更はありません。
