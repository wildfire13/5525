# Historical source provenance and current rule contracts

The seven `test-*.cjs` files originated in the [Web baseline at 0b77f6b](https://github.com/wildfire13/5525/tree/0b77f6bc3f18d02359f7376a0936ad5a8a67a173/prototype/tools). Their module require paths were adapted to the native directory. The porter acceptance/departure assertion was subsequently corrected in [b143630](https://github.com/wildfire13/5525/commit/b14363029587f8f38d20421f9b862a21b0d4962d). The assertion copies and `native/journey.js` therefore must not be described as wholly unchanged snapshots.

Run `node test_engine_regression.cjs` from `native/`. It checks three historical module hashes, seven historical assertion hashes, seven rule suites, and the current semantic porter contract. The old Web folder is no longer part of the current checkout. To additionally compare the historical Web source, use a separate checkout of the fixed [source commit](https://github.com/wildfire13/5525/tree/0b77f6bc3f18d02359f7376a0936ad5a8a67a173/prototype) (or the [removal baseline b723b4c](https://github.com/wildfire13/5525/tree/b723b4cdfb84f1b20fe895502d459092d412effb/prototype)) outside the current tree:

```sh
node test_engine_regression.cjs --source /path/to/historical-checkout/prototype
```

`provenance.json` records hashes from the fixed baseline above (assertion hashes include only the require-path adaptation). The original module hashes are retained. For `journey.js` and `test-porter.cjs`, the runner reverses only the exact recorded b143630 text change **in memory** before comparing with the old hashes/source. Each correction must occur exactly once; reverting it, duplicating it, or changing other bytes fails. No game or source file is rewritten. Even without `--source`, assertion provenance remains mandatory. This establishes historical provenance, not current behavior by itself.

`native/check.py` always runs the local provenance and semantic checks without network access or the removed folder. It no longer auto-detects a sibling `prototype/`. The additional historical-checkout comparison is explicit; it must still fail if supplied source modules or assertions differ from the fixed baseline.

The current contract is [PORTER-ACCEPTANCE.md](../../godot/PORTER-ACCEPTANCE.md): a porter is required when accepting a quest; it does not lock a character into the party or require a porter again at departure. `native/test_porter_acceptance.cjs` tests both the legacy journey and current campaign, including either porter, removal after acceptance, zero-porter departure/save/load, and invalid/empty/duplicate/oversized party boundaries. The campaign's cargo owner selection, cargo retention by reserves, personal inventory, phase/location rules, and existing porter-KO behavior remain separate constraints. `native/check.py` also runs `test_guild_contract.cjs` and `test_quest_cargo.cjs` to preserve ownership, cargo transfer, rollback, and completion rules. The reserve warning UI is covered separately by `godot/tests/quest_cargo_regression.gd`.

These are the rule-only suites: battle, party, porter, Stamp/Snipe, deployment, journey, and play log. DOM suites importing the browser application/cycle code are deliberately excluded, because those do not test the native frontend. Existing deterministic real-process adapter tests remain in `test_journey_bridge.py`; actual GUI evidence belongs in `COVERAGE.md` and the task's observation record.

Some original suites use clearly constructed rule fixtures. Their presence does not establish native GUI reachability or represent ordinary balance/playthrough evidence. Do not update copied assertions or provenance records to hide a divergence; investigate the source version, confirmed specification, and semantic regression before documenting any intended change.

## Updated campaign contracts (2026-10-23)

The four stale test files remain; no test file was deleted. The following mapping preserves their independent checks while separating current rules from historical provenance:

| Previous assumption | Current regression contract |
|---|---|
| `test_campaign_bridge.py`: implicit cargo owner, automatic delivery, trade-in and growing team EXP | The real Node bridge requires an explicit selected porter; missing/nonporter/reserve owners reject atomically. With two porters present, choosing the second must issue cargo to that person only. Arrival preserves quest/cargo without rewards; explicit completion consumes once. `test_repeat_trial_trade_and_questless` is renamed to `test_repeat_trial_inventory_purchase_and_questless`: repeated trips, pure trials, rejected purchases, retained old equipment/re-equipping, per-character battle EXP and no questless delivery reward remain covered. |
| `test_campaign_retreat.py`: shared `inventory` in a current save | Assert version 2 and absent root shared stock; compare complete `characters` (including each bag), party order and other restored resources. Keep cancel/stale/reentry, exactly-once request and refresh checks. `test_inventory_battle.cjs` additionally covers spending personal stock before retreat and version 1 migration. |
| `test_equipment_slots_bridge.py`: every new weapon has no skill | Explicit expected IDs and source/level for virtual offhand fist `itemUse` and wooden two-hand spear `poleVault`, while preserving damage, range, purchase, hand occupancy and save purity/roundtrip checks. The October 19 contract is recorded in [e3a9457](https://github.com/wildfire13/5525/blob/e3a9457f2b4efd5084f502f67f47470dc428069f/docs/feedback-261019.md). |
| `test_campaign_battle.cjs`: arbitrary campaign states equal frozen legacy objects | The shared default match still checks its initial state and all 30 action results against `test_fixtures/campaign-default-reference.json`, independently generated from the frozen Web `battle.js` at the source commit above (SHA-256 recorded in the fixture). Every serialized field remains covered: campaign DEF must be exactly zero before removing that known addition from the reference encoding, legacy `skillStage` must be absent, and the scout intent wording is checked explicitly before mapping it to a named marker. Other differences fail the digest. This fixed scenario does not impose old ambush rules on other campaign states. Original cross-job stamp/heal/snipe, invasion and porter checks remain in the file. |

Frozen legacy full-state process parity remains in `test_parity.cjs`, with original rule suites and source hashes in `test_engine_regression.cjs`. Current positive DEF, cover/formation order, equipment-derived ambush levels/directions and migration are checked by `test_equipment_ambush_def.cjs` (including levels 2/3 only as in-memory test definitions, not new products). `test_team_growth.cjs` checks inert legacy team fields and per-character rewards. Both current suites are mandatory steps in `native/check.py`; no comparison was replaced by an unconditional pass.

Godot frontend checks remain separate. `godot/tests/audio_smoke.gd` first verifies default BGM/voice/SE mute, silent scene synchronization and retained song selection, then explicitly unmutes BGM for all delivered-stream playback checks. `godot/tests/bridge_smoke.gd` verifies the owned Node process is observable before closing and absent afterwards with an independent Node signal-0 probe (only ESRCH means absent). This avoids a second Godot child-PID query after reaping on Unix while preserving residual-process detection; probe errors fail the test.
