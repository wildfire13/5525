キャラクターボイス137クリップ、BGM6曲、装備11案を統合しています。
起動・検証結果・制約は [INTEGRATION-QA.md](INTEGRATION-QA.md)、
装備仕様は [SKILLS11.md](SKILLS11.md) と [SKILLS11-CONTRACT.md](SKILLS11-CONTRACT.md) を参照してください。

Python/Tkのネイティブ画面で遊ぶ5525のプロトタイプです。既定の入口は、拠点を往復し、報酬・成長・キャラ別装備を持ち越すキャンペーン版になりました。今回追加した仕組みの詳しい操作・仮値・未実装範囲は [REPLAY.md](REPLAY.md) にまとめています。

先行する一件完結型のネイティブ移植は、2026-10-02の独立レビューでテスト可能性を確認し、正式プロトタイプに指定したものです。この過去のレビューを、今回のキャンペーン機能すべての実GUI検証済みという意味には使いません。新旧の証拠は [COVERAGE.md](COVERAGE.md) で分けています。元のWeb版と凍結ルールは比較用に保持しています。

## 起動

Python 3 + Tk、Node.js 22以上が必要です。旧版のクラウドGUI記録はPython3.13 / Tk8.6 / Node24.19.0の環境です。今回の集約自動チェックは既存のPython3.12.14 / Node24.19.0で実行しました。コマンド側のTkモジュールは9.0ですが、自動チェックは実Tk画面を開く検証ではありません。追加インストールはしていません。

```sh
python journey_app.py
```

通常起動は `CampaignApp`。元の一件完結型と戦闘単体版は、別々に以下で起動できます。

```sh
python journey_app.py --legacy
python app.py
```

Windowsではリポジトリ直下の `Start-5525.cmd` をダブルクリックしてください。既存Python 3 + TkとNode.jsを確認し、見つからない場合は説明を表示します。インストールは行いません。Pythonは `py -3`、`python`、既存の `%USERPROFILE%\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe` の順で確認します。`NATIVE5525_PYTHON` にPython実行ファイルの絶対パスを設定した場合はそれを優先します。今回、起動スクリプトと `tk_bootstrap.py` は変更していません。

Linuxでは `native/` 内で以下を実行します。

```text
python3 journey_app.py
```

- キャンペーン：掲示板 → 受注または未受注で出発 → 道選択 → 配置 → 戦闘 → 野営 → 二戦目 → 配達/到着 → 次の拠点で続行。買い物・試着・能力配分・町/野営での道具使用ができます
- 編成：アスタリスのギルドで候補11人から最大5人、ポーター最低1人。雇用無料。離脱・再編入でもキャラ別装備を保持します
- 配置：味方ボタンで選択して置き先をクリック、またはドラッグ。味方のいるマスは交換。金枠は陣形、青は通常攻撃範囲、緑枠は奇襲可能な敵
- 戦闘：コマンド → 緑の対象 → 確定。取消/Escでは消費なし。移動の仮位置で攻撃/スキル範囲・陣形・着地点への敵予告を確認できます
- ポーターの陣形強化：使用可能な状態でスキルを押すとYES/NO確認が開き、YESで直ちに実行。盤面で本人を選ぶ操作や、追加の「確定」は不要です。NO・Esc・閉じるでは消費なし
- キャンペーン戦闘の右欄に、金枠3マスの生存味方による占有数、味方／敵それぞれの現在の陣形補正を表示。通常ONは攻撃×1.5・被ダメージ×0.75、強化ONは×1.75・×0.65です。木人の基礎ATK比較は両陣形OFF時の説明で、陣形を作れば表示も変わります
- 移動は一行動です。移動後の攻撃は次の本人の番。敵はAGI順に自動行動します
- キャンペーンの戦闘中は「撤退して出発前へ戻る」から確認後に中断できます。NO（既定）・Esc・確認を閉じるでは変更なし。YESで通常の失敗と同じ受注／出発前の状態を復元し、今回の旅の報酬・成長を取り消します。追加ペナルティなし。ポーターだけ残った局面でも利用できますが、自動敗北にはしません
- 戦闘は別のネイティブウィンドウに開きます。終了後「戦闘を終えて街道へ」。戦闘画面を閉じても、親画面から途中再開できます
- 「進行を保存/読込」は今回のキャンペーン用ローカルJSONセーブ。「プレイログ保存」は診断用の別ファイルです。どちらも手動保存のみで、自動保存・自動送信はありません
- `--legacy` は元の一件完結型です。再挑戦では初期化され、キャンペーンの買い物・連続受注・進行セーブは使いません。旧画面右上には戦闘単体版を開くボタンがあります

## 旧版のQA局面

「QA」と明示された項目は境界確認用です。通常プレイやバランス評価と混同しないでください。

- 戦闘：勝利/敗北/ポーター危機/スタンプ/かばうの固定局面
- 旅程：納期内配達直前・ポーター失敗結果。こちらはルールの公開操作で戦闘を最後まで実行して生成します。HPや報酬の書換えは行いません

これらの旅程QA局面は `--legacy` の検証用で、新しいキャンペーンの通しプレイ証拠ではありません。`tiny_poc.py` には最初の小型GUI実験を残しています。通常の入口は `journey_app.py` です。


`python3 check.py` は実行可能なルール・アダプター検証をまとめて走らせ、`qa-check-report.json` に結果を記録します。戦闘UIのルール検証とセーブ移行は専用テストでも確認します。実GUI・Windows検証は別途必要です。

## 元ソースと構成

戦闘処理は `campaign-battle.js` に一本化しています。全員が戦闘中に敵陣へ移動でき、敵の行動は現在の盤面から即時に選択・実行します。ポーター相対の3護衛マス、最奥到達による突破勝利、ポーター戦闘不能の優先判定を適用します。装備の「侵入」は敵陣への初期配置権を付与します。

- `bridge.cjs`：ローカル標準入出力JSON接続・旅程の画面間処理・読取専用プレビュー
- `app.py`：戦闘画面
- `journey_app.py`：共通起動入口と旧版の旅程・編成・配置・結果画面
- `campaign_app.py`：キャンペーン画面、購入前の確認/試用、ローカルJSONの保存・読込
- `campaign.js`：連続受注、拠点・商店・成長・復元・セーブ検証
- `campaign-battle.js`：共通の現行戦闘エンジン
- `assets/`：元の味方6種/敵4種の透過画像。ファイルは無加工コピー、Tk表示時のみ縮小
- `test_campaign_rule_migration.cjs`：旧戦闘中セーブをアスタリスへ戻し、所持品と元データを維持する移行検証

## 明示している違いと限界

- ネイティブ2D画面です。Web版Three.jsの立体街道/荷車、被弾/回復パーティクル、登場アニメーションは再現していません。数値・予告・結果は盤面/文章で確認できます
- 通常攻撃・アイテム・防御にも追加の確定操作があります。ポーターの陣形強化はYESで直ちに実行する確認方式です
- 盤面は共通10×5座標を一続きに表示し、陣地色で左右を区別します
- 本書の実GUI証拠はクラウドLinux上の検証です。Windowsランチャーを同梱していますが、Windows実機の検証は別途必要です。インストーラーはありません
- Tkのアクセシビリティ情報は汎用X11コンテナーのため、実GUI検証はスクリーンショットと座標入力を使用しています
- 今回のキャンペーンには手動の進行セーブ/ロードがあります。未保存状態のクラッシュ復旧・自動保存はありません。元Web版と `--legacy` にはこのキャンペーン機能を移していません
- 完成版の全装備枠、新規キャラ/主人公作成、ジョブ解放クエスト、便利系スキル、別セーブ統合は未実装です。装備は武器セット/身体防具の2枠、防具は最大HP増加で試作しています。詳細は [REPLAY.md](REPLAY.md)
- すべての敵抽選/編成を実GUIで通しプレイしたという意味ではありません。境界・組合せはルールテスト、代表フローは実GUIで分けて確認しています
- 新キャンペーンのファイル保存・再起動後の読込・ログJSON出力を実GUIで確認済み。OSの保存失敗時に元ファイルを維持する処理は自動テストで確認し、実GUIの権限エラー操作とは別扱いです


## Windowsの既存Codex Python用起動補助

確認されたPython 3.12.14 x64 / Tcl・Tk 8.6.12の既存Codex runtimeでは、スクリプトが存在していても通常のTk生成が失敗しました。同じDLLで実行ファイルを登録し、一時Tclインタープリターで `pwd` を評価・破棄してからTkを作る順序で、実際の旅程ウィンドウ生成が成功しています。根本原因が特定できたという意味ではありません。

`tk_bootstrap.py` は確認済みのディレクトリ構成・Python版・DLL版・スクリプト版にだけ適用します。TCL_LIBRARY / TK_LIBRARYはそのプロセスだけに設定し、既に別のパスが明示されている場合は変更しません。通常のPython環境では従来通りTkを起動します。ランチャーの確認と実アプリは同じ補助を使います。ランタイム更新後に再発した場合は新しい版の診断が必要です。インストール済みファイルやユーザー全体の設定は変更しません。

モック検証は7件です。Linux上の検証でWindows DLLを実行したという意味ではありません。Windowsの実機確認とスクリーンショット確認の有無は分けて報告します。
