# 施設NPCの別コミット実験

2026-10-24。編成・商品比較の `b465bc7` から分離した表示の試行です。ゲームルール・native・保存形式・NPC会話・報酬は変更しません。

## 表示と訪問

ユーザー提供の原本7枚をバイト単位で保持して組み込み、施設背景の右側へ表示します。既存の背景・暗色レイヤー・前景の3層を維持し、前景の中に左の操作領域と右のNPC専用領域を置きます。画像は全体の縦横比を保持し、顔・ハンマー・盆を切り抜きません。領域と画像はマウス入力を無視し、フォーカスも取りません。

武器屋は専用の `RandomNumberGenerator` で `randi_range(0,1)` を入店時に一度だけ使用します。売買、取消、人物切替、再描画、ウィンドウのサイズ変更では抽選しません。退店後の再入場で再抽選し、連続同一人物を許容します。他5施設は固定画像、出発画面にはNPCを表示しません。背景用RNG・Node側のゲーム進行RNGは利用しません。

ギルドの列幅は割当領域に追従させ、1180×812でも氏名・HP/MP・操作欄を保ちます。宿屋は従来の180px人物カードと横スクロールを保持します。1120×720未満では操作領域を優先してNPC列を表示せず、元のコンパクトUIを使います。再拡大時は同じ滞在の人物が戻ります。

ロード・新規・戦闘への移行と接続断は訪問を終了します。切断中の旧画面の再描画では施設を再入場扱いにせず、NPCを再抽選しません。再接続は既存の拠点画面から始まります。施設背景そのものが欠損した時は既存の簡易表示へ戻り、NPCも表示しないフォールバックを維持します。

## 検証と評価範囲

原本のSHA256、寸法、RGBA、全バイト・合計サイズを照合しました。新規 `facility_npc_regression.gd` と現行UI runnerを接続し、訪問固定、等確率二択の正規呼出、保存/RNG独立、売買・取消、人物切替、resize、再入場、コンパクト表示・再接続を検証しました。

新規NPC回帰192/192・独立境界追試24/24、現行UI runner25/25が合格。原本は全SHA一致・13,515,244 bytesを維持。ERROR・FAIL・leakは最終ログにありません。

実描画・OS入力は `facility_npc_gui.gd` を用い、1920×1080と1180×812で全6施設と武器屋2人を撮影しました。NPC上のクリックでゲーム操作が起きないこと、購入取消・人物詳細切替・ギルド復帰・宿の取消/確定・再入場を実XTestで確認しました。テストは隔離したXDGプロファイル、Dummy音声、BGM/ボイス/SE OFFです。両解像度のOS試験は各99/99、NPC追加後の最小画面でのA操作追試も65/65が合格しました。

画面比較と性能サンプルはリポジトリ外の実験証跡に保持します。NPC前後を同じ武器店・500G合成セーブ・背景seedで順次実行し、各サイズ180フレームを採取。中央値はFHDで24.02→25.95ms、1180幅で10.64→13.67ms、テクスチャメモリは約8MiB増でした。起動は1038→970msで、単発値のため速度改善とは判断しません。画像追加には描画コストがあり、採用時の判断材料として残します。ソフトウェアOpenGLでの局所測定はWindows実機や本人の操作感を保証しません。実聴、Windows、CI、本人プレイ、ユーザーPC反映は未実施です。
