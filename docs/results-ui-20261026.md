# 確定済みリザルトの表示

戦闘勝利と配達達成を別のリザルトとして表示する。報酬・経験値・成長の規則は既存の native campaign に従い、この画面から付与処理を呼ばない。

## 確定境界

- 戦闘勝利: 既存の戦闘終了操作による `finishBattle` 成功時。処理前後の campaign roster と所持金の差を取得する。戦闘終了ボタンを押す前の勝利状態では未付与の値をリザルトにしない。
- 配達達成: 広場の配達操作による `completeQuest` 成功時。通常・遅配は既存 result.outcome と確定額を表示する。目的地への `arrive` だけでは配達報酬は確定しない。
- 敗北・無効な操作・単なる到着は勝利リザルトにしない。
- `main.update` の後続到着処理と各報酬確定を分けて観察し、戦闘と配達の金額を合算して誤分類しない。

表示する値は実際の所持金差、各同行者の累計経験値の前後差、レベル、確定した能力/スキルポイント増分。敵戦闘不能人数と行動数も存在する battle データだけを使う。報酬量の表示用定数は追加しない。

## 保存と操作

セーブの形式・保存先は変更しない。戦闘リザルトはセッション中の読み取り専用 receipt で、保存再読込後に存在しない前後値を再構成しない。保存済み配達結果は既存 result に記録された金額と経験値を表示できるが、記録されない成長前値は省略し、その理由を表示する。

閉じると配達結果だけを既存 `acknowledge` で一度進める。戦闘結果を閉じる、メニューから直近結果を開き直す、保存ダイアログを取り消す操作は報酬を呼び直さない。連打には receipt sequence と active ガードを使う。広場に戻るほか、既存の目的地施設への導線も保持する。戦闘中のリプレイ表示は許可しない。

ローディング画面が終了してから結果を表示する。全画面の入力遮断面を持ち、結果自身のボタン・スクロール・保存ダイアログへは GUI 入力を通す。背後の盤面や共通メニューは操作できない。Tab/Shift+Tab、上下・PageUp/Down/Home/End、Enter、Escape に対応する。

## 視覚設計

専用のオリジナル生成紋章を戦闘と配達で分け、藍色・金色のフレームに導入見出し、確定金額/経験値、人物ごとの成長を配置した。0.22秒の控えめな表示アニメーションは入力待機を追加しない。主要操作は固定し、同行者の長い一覧だけをスクロールする。狭画面では紋章と余白を縮小する。経験値増分は折返さず、人物名とレベル・累計経験値は別領域で読む。

`godot/assets/results/manifest.json` にランタイム画像の寸法・透過範囲・SHA256を記録。画像は640×768 RGBA。戦闘は交差した刃と月桂冠、配達は巻物/封蝋と方位の意匠。競合の画像・紋章は使用していない。

## 検証入口

- `godot/tests/results_fixtures.cjs`: 正規 native validation を通る勝利・通常配達・遅配・敗北境界を生成する。戦闘勝利 fixture は終了境界を試すための状態であり、プレイで敵を倒した映像とは区別する。
- `godot/tests/results_regression.gd`: 確定差分、通常/遅配、報酬と保存結果の完全一致、連打/再表示/再読込、敗北、画像読込、FHD/1180×812/960×540/復帰の画面内収容を検証する。
- `godot/tests/results_gui.gd`: X11 OS入力で既存終了ボタン/配達操作、保存取消、背景遮断、スクロール末尾、施設遷移、Tab/Escape、再表示を操作し、7場面を撮影する。音声3種はOFF。
- `feedback_261019_3.gd`: 配達結果の正規入口を専用リザルトへ更新。報酬/history不変の期待値は維持する。

実機Windows/DPI、ユーザー本人の評価、音声品質は別確認とする。

補助的に未登録の旧 `ui_review_fixes.gd` を同一ソースで基点 `e5d4d5f` と比較した。基点は59件到達（39成功/20失敗）でResultShop不在のnull参照により結果ケースの残りが未到達、現行は83件到達（57成功/26失敗）。共通到達の新規失敗はなく、共通失敗19件、基点だけの失敗1件、基点未到達の現行失敗7件に分ける。現行のみの7件は装飾品のcanonical product/allowedSlotsを単一slot一致と誤認する条件2件と、travel自動ack後に非表示の配達用ボタンを検索する旧結果期待5件だった。非表示ボタンは祖先shadeとactive/sequenceガードにより実操作できない。shop_viewと旅行結果自動ackは基点の既存処理を保持し、この旧試験に合わせた製品変更はしていない。未到達24件の完全な動的前後比較を実施できたとは扱わない。
