# スキル・汎用エフェクトと入力修正の実験

基点は `3482e809`。`experiment/movie-ui-brushup-20261024` 内の表示・入力変更。ルール、能力、乱数、行動解決、セーブ、既存施設NPCは変更しない。

## 演出の対応

`godot/skill_effect_layer.gd` は新規オリジナルの投影線描画。画像・音声素材や追加依存は不要。`battle_board.gd` が既存の確定した presentation の発動と実結果を渡す。マスから毎フレーム投影し、カメラ変更に追従する。入力を受けず、HP・範囲・浮動数値より下に描画する。

| 既存の処理 | 表示 |
| --- | --- |
| 足払いの発動 | 正規の周囲セルに低い弧。成功・転倒の印ではなく発動範囲の表現。既存skip状態の単純差分を成功判定に使わない。 |
| ヒールの発動／実HP増加 | 使用者の小さな緑の輪／実際に回復した人物の上昇粒子。全快で使用不可なら再生しない。 |
| スタンプの発動／実HP減少 | 正規の中心と両隣3マス（盤端は欠ける）の圧力線／実被害者の短い命中光。かばうで移った被害者も別に扱う。 |
| 通常攻撃の発動／実HP減少 | 使用者セル内の短い方向線／実被害者の共通命中光。遠隔も無条件に斬撃へ置き換えず、予約マスが空なら命中光は出ない。 |
| 防御コマンド | 使用者の低い盾形輪郭。防御姿勢の表現であり、新しい成功判定ではない。 |
| 防御中または肩代わり先への実被害 | 共通命中光に低い輪郭を併記。軽減量や成功率を推測しない。 |

既存の action/hurt 0.42秒、heal 0.30秒に重ねる。追加待ち時間・画面揺れ・音声なし。確定前のプレビュー、取消、不正行動では開始しない。同一フェーズの二重通知、次フェーズ、画面非表示、ロード・終了時に残留しないようクリアする。

## 入力修正

- 所持品から装備先へドラッグし確認を取り消した後、同じ品目を再ドラッグできない問題：比較窓が元の品名を覆うことと、戻り先が比較ボタンになることを修正。品名・一覧位置・所有者・指定手の文脈を保つ。比較本文のスクロールは維持する。
- 行動順にTabフォーカスがある時だけ左右キーで1枚分スクロール。盤面や他の操作へフォーカスがある時のキーを奪わない。既存の5枚・マウススクロール・順番詳細を保持する。

`skill_effect_fixtures.cjs` は既存APIから23局面を組み立て、直接解決とpresentation経由の最終値・乱数呼出回数・セーブ往復を照合する。足払いの成功／失敗／既存skip／空／盤端、回復上限・自分・全快、スタンプ盤端・空振り・かばう・次行動者、近接／遠隔／防御／最低ダメージ／肩代わり／予約マス空振り／連続攻撃を含む。

標準UI runnerは34/34、nativeは23/23で合格。新規回帰は演出統合589/589、再ドラッグ54/54、行動順50/50。描画層の独立検証3376/3376も確認した。実X11は1920×1080、1180×812、1280×800の計19局面をOS入力で確定し、連番・実結果・消失を記録。3方向のカメラ角、ズーム14〜20も対象。所持品は1180/1920幅の実OS入力で各52/52、行動順は960/1180/1920幅で103/103。基点でも同じ操作を行い、既知の閉塞と横スクロール不可を再現した。記録フレームの時刻から7本の音声なしMP4を作成した。収録負荷を含む動画の秒数とコード上の待ち時間は区別する。

最終収録は診断フックの初期化順を修正した後に76/76で再確認。実draw通知と画像の連番を保存し、描画領域と発動・消失を照合した。
