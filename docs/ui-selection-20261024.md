# 編成・商品比較の実験

2026-10-24。基準 `ff044ed9d21d5ea49d287cf39ed962799bce3354`、ブランチ `experiment/movie-ui-brushup-20261024`。ローカル実験、評価前。main・GitHub・ユーザーPCへの反映は行っていない。

## 変更

- 控えの既存職業で絞込み。参戦者は常に表示し、残り枠を併記。見えなくなる控えの選択は氏名つきで解除する。職業ごとのスクロールと、詳細を閉じた際の選択文脈を維持する。
- 商品名から人物・装備枠別の比較へ進める。比較は既存 `previewGear` と所持装備の表示を再利用し、氏名、枠、現在品→候補品、符号つき差分、効果、装備条件を表示する。人物・枠切替でセレクタを作り直さず、古い非同期応答を無効化する。
- 購入費用は通常購入の `purchaseQuote` を使用する。装備した場合の性能比較と、所持品への購入を区別する。従来の購入手順も維持し、受取人選択にも品名・費用・残金を残す。
- 数量売却は `saleQuote` の所有者・品名・数量・受取額・売却後所持金を、数量変更に追従して表示する。消耗品の既存1個/5個購入には総額・残金または既存の不足/上限理由を併記する。
- 所持装備の比較にも対象者・枠・現在品と候補品の見出しを加える。ゲームルール、保存形式、ID、報酬、成長・結果表示は変更しない。

## 検証

Linux / Godot 4.6.3 / X11・ソフトウェアOpenGL。合成セーブと隔離XDGプロファイルを使用し、BGM・ボイス・SEは全てミュート、出力はDummy。

- 新規 `brushup_formation_regression.gd`：26項目合格。
- 新規 `brushup_comparison_regression.gd`：58項目合格。正規比較との一致、プレビュー不変、取消、人物/枠切替、遅延応答、装備不可、資金不足、数量売却、上限での原子的拒否、重複確定、接続断UIを含む。
- 現行UI runner：変更前22/22合格。途中で比較見出しの部分データ呼出への不備を検出・修正。NPC追加後の最終差分でも、既存22＋新規3（Aの2本・NPCの1本）の25/25コマンドが合格。
- `python3 native/check.py`：23/23段階合格。Python162件中161件合格、Windows固有1件スキップ。
- 追加の拳・返金冪等性・戦闘内外アイテム・ポーター正規条件・荷物UI・床マス検証も合格。
- 1920×1080と1180×812で実描画とXTestのマウス/キーボード操作を検証。編成選択/詳細/戻る/絞込み/入替、比較対象/枠切替、購入、売却取消、人物切替、再読込を確認。直接入替は2クリック、既存購入は3クリックのまま。
- 同じ合成セーブ・表示用乱数seed・解像度で変更前後を撮影。実画像と全ログはリポジトリ外の実験証跡へ保存した。元資料・私的な観察台帳はコミットしない。

実行例：`python3 godot/tests/run_inventory_header_261020.py --evidence <checkout外の新規ディレクトリ>`。
OS入力は隔離したX display上で `DISPLAY=<display> BRUSHUP_GUI_WIDTH=1920 python3 godot/tests/run_facility_gui_261022.py --script brushup_gui --evidence <新規ディレクトリ>`。1180も別プロファイルで実行する。

## 制約と次段階

通常購入の既存予告APIは受取人未指定であり、対象者ごとの保存サイズ/極端な所持数上限の事前判定APIはない。このため比較画面は「購入を確認」とし、受取可否は確定時に判定すると明記する。10^10個の境界では確定が拒否され、所持金・在庫・セーブが不変であることを確認した。別の上限計算や新しいバックエンドAPIは作っていない。

勝利・成長結果の改善は次段階。NPC素材の表示はこの変更から分けて評価する。Windows実機、実聴、本人プレイ、ユーザーPCへのpull、CIは今回のローカル検証の成功には含めない。
