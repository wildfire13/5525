# 単発クエストQA：会話Esc・確認画面の追加修正候補

基点: `f177e356f1c110575adcd326d6154da970840606`（draft PR #3）。先行2件とは別のローカル候補。追加の公開・PR更新・mainマージは行わない。

## 確定した不具合

### 1. 会話途中のEscが背面へ届く

- 単発3件で、表示途中または1行を全文表示した状態のEscが会話に消費されず、背面の掲示板がローカルマップへ移る。会話は残ったままになる。
- 納品成功リザルトから開いた会話でも同じ原因があり、背面のリザルトを閉じて結果をacknowledgeする。
- 原因は `quest_dialogue.gd` が選択肢表示中にしかEscを処理しないこと。末尾の選択肢では既にEscで閉じる実装があり、共通ヘルプもEscで閉じる操作を案内している。
- 修正は会話の全段階でEscを先に処理し、既存の `modal_escape_frame` と入力消費を使って会話だけを閉じる。会話内容・受注条件・納品・報酬の変更はない。

### 2. 確認画面の本文と背景がともに暗い

- 単発QAの人工セーブ読込で発見した共通UIの不具合。単発固有ではなく、読込・再接続・入れ子の確認にも共通する。
- 現行テーマで本文は `#29332f` へ変わっているが、`AcceptDialog` のパネルが既定の濃灰色のまま。設定色のコントラストは1.254:1。
- 共通 `confirm()` のパネルだけに既存の `mock_shell.surface_style()` を適用する。本文とボタン、タイトル、確認文、コールバックはそのまま。新しい色やデザイン方式は追加しない。
- 背景90%不透明、本文100%不透明。黒・白の背景へ合成した設定色のコントラストは9.89:1／12.46:1。ピクセル実測値ではない。

## 再現と回帰

専用 `quest_modal_regression.gd` を既存の新UIランナーへ追加する。新規ゲームと人工ファイルのみを使い、各実行のHOME・XDGを分離する。

- 修正前は83項目中27失敗。会話Esc24項目と確認本文コントラスト3項目が失敗。
- 同じテストで修正後83/83成功。独立レビュー側の別プロファイル実行も83/83成功、ERRORなし。
- 3クエストの表示途中・1行全文・選択肢で、`Input.parse_input_event` によるEsc、押しっぱなし相当のecho、再読出しの状態不変を確認。
- 納品成功後は会話だけを閉じ、背面リザルト・保存状態・報酬を維持することを確認。
- 実際の `load_dialog()` 経路へ人工ファイル選択を渡し、確認前・取消時の保存状態維持、確認後の読込、元ファイル不変を検証。OSファイル選択そのものは信号で代替する。
- 再接続ボタンの確認ハンドラで、取消時のエンジン世代・保存状態保持を確認。接続障害からの実復旧を検証したものではない。
- 入れ子の長文確認、スクロール末尾、キャンセルへの初期フォーカス、二重確定でも1回のみ実行することを確認。
- 先行の期限失敗66項目、報酬表示155項目、サービスUI回帰も合格。
- 最終候補で新UI全19工程・旧UI全66工程・native集約32工程がすべて合格。nativeはPython213件（既存1skip）を含む。旧UIは既存の直列3組（23/22/21工程）を変更せず完走。
- GitHub CIはこの追加候補では未実行。先行PR #3のCI成功とは区別する。
