# 個別装備・スキルアイコンの適用候補

基点はmainへ統合済みの `b43351c5c6f24def8df51e3e89c05b6fd55c1821`。同じ実験ブランチに変更を分離し、今回はローカル検証・commitまでとする。mainへの再マージ、PC操作、CCT、temporary-storage、共有設定は対象外。

## 対応と表示経路

- 42枚の装備画像を既存47IDへ、新しい19枚を既存スキルへ割り当てる。PNG61枚は提供された64×64 RGBAファイルと完全に同じバイト列。原画の描き直しや名称・役割の変更はしない。
- 装飾品5組はslot1/slot2で同一画像を共有する。末尾1/2をスキルLvと解釈しない。装備の強化値からスキルLvも推定しない。
- 既存のヒール・奇襲・足払い・陣形強化の画像とレシピ、指定の拳を保持する。空枠に画像を追加せず、拳を実アイテムへ戻さない。未確定上位装備・上位Lvを追加しない。
- `approved_v56/recipes.json` が優先経路。旧equipment mappingも同じ新画像47IDへ揃え、未登録だった鉤縄・カンフーパンツ系を含める。カテゴリ・職業・施設・防御コマンド用画像は変更しない。スキル「かばう」と防御コマンドも別の名前空間のまま。

新画像と技術manifestは `godot/assets/individual_icons`、CSV対応表は `docs/individual-icons-mapping.csv` に置く。CSVは翻訳素材として自動取り込みされないようGodotのresource treeから分離する。原画ZIP、転送情報、私的資料はリポジトリへ加えない。旧素材は削除せず、既存4種と拳の参照もそのまま残す。

## Lv合成と読みやすさ

旧69×68の合成枠を64×64へ統一し、既存のLv画像を21px内へ縮小して右上(43,0)へ一度だけ合成する。スナイプの予約領域は完全透明、アイテム使用の原PNGにある微小な半透明端も原本どおり保持する。旧仮バッジは新個別画像へ重ねない。ゲームの正規名称内の「（仮）」や既存の試用状態を勝手に正式化しない。

Lvは足払い・アイテム使用1〜3、奇襲・スナイプ1という既存対応を保持し、未対応レベルは従来の画像fallbackを維持する。アイテム使用Lv2は描画単体で検証し、旧拳＋1をゲーム内へ復活させて検証しない。

24pxの戦闘行ではLv数字が読み取りづらかったため、Lv画像を持つ行だけ32pxへ広げ、同じ正規sourceレベルを文字でも併記する。選択印・説明ボタン・スキルID・可否判定は保持。非Lvスキルは従来の24px。細い槍や挟撃の小表示は、既存の名前併記と併せて識別する。
