# 独立した開発情報ウィンドウ

## 分類と設計

開発専用: 処理待ち・演出・予測/見積待ち・エンジン待機/切断・ローディング中の内部状態、要求の成否と所要時間。共通下部欄の「処理中…」「演出中…」、戦闘HUDの汎用「演出中…」ラベル/無操作ボタンを通常ゲーム面から除く。

プレイヤー向けとして保持: フォーカス操作説明、エラーと対処案、保存トースト、受注/報酬結果、ローディングスチル、戦闘の技名・対象・HP・実結果。手番の「実行中」は行動者の識別情報であり、内部待機表示とは分けて保持。ゲームの処理順・操作ロックは変えない。

メニューの「開発情報（別ウィンドウ）」から明示的に開く。通常起動では作成しない。Godot Window.force_nativeを用い、ゲームの埋込子窓設定は維持。非モーダルで、閉じる/Escapeは開発窓だけを隠す。ゲーム終了時には同じプロセスとともに終了する。

ログはメモリ内の最新200件。固定の状態名と真偽値、要求がゲーム/ファイルのどちらか、成否、時間のみ。引数、保存データ、人物名、パス、通信本文、エラー原文を収集せず、外部送信・ファイル保存・コンソール転送は行わない。非表示中はテキストUIを更新せず、状態監視は5Hz。

先行の吹き出し/パーティ位置固定を保持。ローカル実装・検証・commitのみ、push/CI/本人PC操作なし。

## release無効化

判定は `debug_window.gd::is_enabled()` の `OS.is_debug_build()` に集約。releaseでは開くメニューを作らず、`open/build`を直接呼んでもWindowを生成しない。状態監視・要求ログ収集も停止し、ゲーム側の制御には影響しない。コメントアウト運用は不要。

## 検証結果

- Linux Godot 4.6.3、X11/llvmpipe、音声3種OFF。独立窓GUI60/60、18 OS入力。FHDと960×540で別OS Window ID、非埋込・非モーダル、Escape/close要求、入力非混線、エラー保持、パーティ座標不変、200件上限と消去を確認。
- 実戦GUI64/64、7 OS入力。通常攻撃/ヒールの発動から効果完了を通し、汎用内部ラベルがなく技名/対象/HP/数値が残る実画像を確認。正規戦闘結果一致・演出残留なし。
- 関連回帰8/8: feedback_261019_3、frontend_smoke、battle_layout_f2、loading_screen_check、painted_vfx_regression、status_footer_stability、debug_window_check、quest_board_feedback3。
- 最初のnative窓設定順序の不備を修正。Windowを非表示にしてからforce_nativeを指定する。狭画面の初回試験はメニュー内スクロールなしで対象外の位置をクリックしたため、実OSホイールを含めた手順へ是正し再検証した。
- release判定をfalseにした分岐試験で、直接open/buildしても生成・監視・ログ収集なしを確認。実際のrelease exportバイナリは今回用意していない。Windows実UI/DPI、実GPU、本人PCは未確認。CIは起動しない。

ゲーム側の競合操作を拒否するエラー応答「処理中です」はプロトコル上の失敗理由なので変更しない。定常的な内部状態ラベルとは区別する。
