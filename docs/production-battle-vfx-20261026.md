# 戦闘演出 graphics と結果画面

## 目的と境界

既存の通常攻撃・命中・足払い・ヒール・スタンプ・防御を、独自に制作した透過graphicsと3D盤面上の時間制御で表現する。競合作品の画像、動画、紋章を転用しない。結果画面の確定境界は `results-ui-20261026.md` を参照。

ゲームの判定・数値・乱数・保存形式・行動フェーズは変更しない。既存のpresentation acknowledgeまでの**表示時間**を技別に調整する。入力待機を余韻の寿命へ結び付けず、同一action内では短い尾を保持し、次のaction、終了、ロードでは全消去する。音声追加、全画面フラッシュ、画面揺れはない。

## graphics と実装

`assets/vfx_production/manifest.json` の19枚は正規imagegenによるオリジナル制作。透過余白、アンカー、サイズの技術正規化後のRGBA画像を使う。姿勢の原画は変更せず、専用差分を別ファイルとしている。

- 足払い: 太さと擦れのある地表の筆致、粗い土煙、破片、腰を落とす/脚を伸ばす姿勢。
- ヒール: 薄絹状ヴェール、葉形光片、柔らかな中心光。身体の実スプライト中心に追従した後景と前景の分割で包む。
- 防御: 青鋼/金縁の盾板と独自紋章、接触反射、ガラス状破片。盾を常時大きく表示しない。
- 通常攻撃/命中: 刃の一筆、方向のある飛翔/突き、圧縮された接触光を分離。
- スタンプ: 垂直の落下筆致、非対称の接地圧力/ひび、単独土塊、木槌を上げる/振り下ろす姿勢。地面は恒久変更しない。

`skill_effect_layer.gd` がworld座標、向き、寿命、前後層、接触、cleanupを制御する。`vfx_painted.gdshader` はalpha合成・走査・擦れ消失・局所面波と正規対象マスのmaskを担当する。全画面のUI画像として貼らず、HPと文字は従来のoverlayが前面を保つ。素材は盤面生成時に一度読み込み、共有shaderはその初期フレームの小さな透明quadで先行描画する。現行mainでは盤面自体を起動時に生成しているため、この先読みは戦闘開始の処理より前に行われる。戦闘の初回使用へ読込を集中させず、追加の最低待機時間も設けない。将来の追加素材を戦闘前loading下へ遅延ロードする拡張とは区別する。

## 確定した対象と結果

- 足払いはダメージ0。`resolved_status` は正規処理の成功代入を観察し、既にskip状態でも今回成功/失敗を区別する。発動brushは正規周囲マスだけ。転び反応と『手番スキップ』は成功した対象だけに出す。
- 通常攻撃の軌跡は `attack_visual` の正規 `reachFilteredPower(...).weapons` の寄与武器だけから選ぶ。同時寄与ではbase atk最大のものを表示上の代表にする（同値は元順序）。別の攻撃回数や威力を作らない。敵予約cellは古い対象者を追尾せず、空振りにも命中光や数値を出さない。材質/種別の根拠がない敵・legacyは中立の小さな予備光に留め、無条件に斬撃を描かない。
- HP接触光と浮動値は既存hurtの実被害者/実差分だけ。かばうでは指定位置への軌跡と実被害者を分離する。防御中にも実ダメージがあれば値を残し、完全防御を示す文言を作らない。
- ヒールの発動と回復結果は分離する。回復光のピーク/数値は実際の正増加だけ。上限では増えた値、全快では取得していない回復量を表示しない。
- スタンプは正規の中心＋両隣3マス（盤端は欠ける）。落下前に床の土塊を出さない。地面の接触表示と実hurtは独立し、空振りで敵命中を捏造しない。

## 表示時間

| 表示 | 秒 |
|---|---:|
| 足払い発動（予備→低い回転→反応→土煙） | 0.76 |
| ヒール発動 / 実回復 | 0.36 / 0.58 |
| 防御姿勢 / 防御・肩代わり被弾 | 0.58 / 0.30 |
| 通常攻撃予備・軌跡 / 通常被弾 | 0.30 / 0.20 |
| スタンプ持上げ・落下 / 実被弾 | 0.34 / 0.24 |

同一技の複数hurtは元の順序のまま。move/jump、他の既存技は元の処理を保持する。`legacy_skill_effect_layer.gd` は対象外の旧packet互換経路として残す。

## 姿勢素材の適用範囲

足払い差分は既存 `knight.png` の標準味方だけ。木槌差分はさらに実装備が木製槌の場合だけ。カスタム人物素材・他のキャラ・鉄製槌へ別人物や木槌を強制しない。その場合は既存キャラを小さく動かし、専用の技graphicsを使う。全キャラ/全武器の姿勢原画が揃ったとは扱わない。各終了経路で元のtexture/pixel_size/position/modulateを復元する。

## 品質確認の区別

`skill_effect_fixtures.cjs` は正規処理と表示観察経路の結果・乱数消費・保存の一致を検証する。`skill_effect_regression.gd` は23境界、`painted_vfx_regression.gd` は素材・対象・確定値・姿勢所有権・連続処理のcleanupを検証する。既存マス基準入力、セーブ、拳、受注条件のテストは維持する。

実画面QA・独立の視覚評価・動画/連番出力は自動テストとは別に記録する。ソフトウェア描画環境の録画速度をユーザーGPU性能として扱わない。連番からの固定30fps動画は実時間FPSの証明ではない。音声OFFでの確認を実聴済みとせず、Windows実UI/DPIは別確認とする。

スタンプのかばうでは、実hurt側の接触・土塊・数値は表示するが、肩代わり成功の専用barrierは新しい確定metadataがないため推測で追加しない。指定中心との不一致だけでは、複数対象の通常被害と肩代わりを区別できないためである。

負荷の比較条件・数値・限界は [専用VFXの負荷比較](production-battle-vfx-performance-20261026.md) を参照。

## ローカル検証結果

- 標準43/43、native23/23段階、正規fixture23ケース。最終変更後の関連3試験（skill_effect/painted_vfx/results）も成功。
- 専用painted境界776/776、canonical演出589/589。素材/対象/実数値/入力非遮断/乱数と保存/重複packet/終了/ロードの後始末を区別して検証。
- Linux X11実OSの386項目/86入力、最終sourceの追加83項目/18入力。斜め遠隔、960×540、演出中の実ウィンドウ縮小と復帰、かばう、空振り、取消を確認。結果画面は別担当の実OS57項目/18入力と主要button focus再試験21項目/7入力。
- 独立連番/実画像評価でhealの非対象重なり、stampの床効果隠れ、結果button focus判読性を検出し、修正後に再確認。独立source/因果probeでcompact復元とprojectile方向を検出・修正し、新regressionへ追加。
- 固定30fps書き出しは旧/新同じ戦場・zoom16.5・yaw0・pitch0.7で3回ずつ。足払い/ヒール/防御の代表動画、通常近接/遠隔、stamp/cover/missの連番と動画を作成。管理ポリシーによるbrowser再生拒否があるため連続動画視聴は未実施。連番実見・OS操作・エンコード検証と区別する。
- ユーザー最新指示でpush/公開/CI起動は保留。本人PC操作、実GPU、Windows実UI/DPI、音声実聴、長時間soakは未実施。
