# 施設・12人パーティー・戦闘出場の操作整理

## 対象と判断

戦闘VFXと確定済みリザルトの改修に続け、確認済みの4画面の要望を適用する。装備実装テンプレート、強化、納品の新機能は対象外。施設の入口に未実装領域を無効状態で確保する。

パーティーの所属上限を12人とし、戦闘出場上限5人とは別管理する。現行の実在名簿は11人なので、実操作の11人到達と12人満員の合成境界試験を区別する。人数増加に伴う新人物・能力・報酬は追加しない。

ポーターが必須なのは既存の受注時。受注後の出場開始へ新しい必須条件は加えない。既存の死亡ポーターの出発制限・敗北判定は維持する。

## 実装

- 施設の入口で購入・売却等を選び、売買の「戻る」は入口、入口からは広場へ戻る。既存背景・NPCを使い、台詞領域を分ける。道具店の1個/5個購入も共通配置へ統合する。道具売却は正規処理が存在しないため無効状態で理由を表示する。
- 売却は下部人物の初回クリックで所持品を商品領域へ表示し、同じ人物の再クリックで人物詳細を開く。別人物への変更は一覧・詳細・選択色・見積りを一緒に更新する。数量・総額・残金を常時表示し、確認取消では数量・選択を保持する。購入の人物操作は従来通り。
- 商品ヘッダーと行の右端を整列し、取引結果は既存の保存通知と同じ一時通知へ。別プロフィールのロード時には古い通知を消す。
- ギルドの左右名簿を縮め、追加・人物詳細・除外を中央縦列へ。下部人物列はコンパクトな顔カード、左右ボタン、横スワイプで全員へ到達できる。スワイプは人物クリックを発火しない。
- 戦闘準備にも下部人物列を表示する。重複する詳細ボタンを準備中のみ隠し、カメラ操作説明を敵情報の下へ移す。陣形と開始ボタンの下端を揃え、固定フッターが配置マスを隠さないよう準備時だけ構図を補正する。
- 配置済み味方の盤面外への意図的ドロップで除外、控えの有効空きマスへのドロップで追加、味方マスで置換する。満員でも置換可。敵側・UI操作領域・ウィンドウ外・ESC・古いpayload・重複追加は変更なし。旧データに出場不能者が残る場合のみ顔カードに「除外」を用意し、生存控えへ交代できるようにする。

## 正規処理と保存互換

`native/campaign.js` の `deployment_assign` が人数・生存・位置・重複・開始可否を検証する。任意の `battleSelected` を既存形式に加え、所属 `selected` と分離する。旧データで任意項目がない場合は従来の出場者を引き継ぐ。出場しない所属者を盤面へ生成せず、HP・MP・アイテムは変更しない。既存の旅全体の経験値・休息の扱いは維持する。同職者の行動順は出場順に正規化し、奇襲配置の衝突だけを自陣の最寄り空きマスへ補正する。戦闘計算・乱数を変更しない。

施設の売買は既存の正規見積り・確定APIを呼び、UI独自の価格計算や消耗品売却制度は追加しない。非同期見積りは人物・品目・数量・世代・接続・保存状態を照合し、古い結果を再利用しない。

## 検証の入口

`python native/check.py`、`node native/test_deployment_roster.cjs` と、`python godot/tests/run_inventory_header_261020.py --evidence <checkout外の新規ディレクトリ>`。新規の施設・ギルド・D&D・人物列の回帰を標準runnerへ登録する。既存の資源・取消・保存・ホバー・結果・ロード・演出テストを保持し、施設入口と新人数に対応する経路/表示期待を更新する。

GUIは隔離プロフィール、BGM/ボイス/SE OFF、Linux Godot/X11のOSマウス・キー入力で実施。FHD、1180×812、960×540、画面復帰、無効drop、取消・連続操作・数量・保存復帰を分けて記録する。公開後は実装者と別の担当が正確な反映SHAで通常導線を連続試遊する。

クラウドはCPUソフトウェア描画。Windows実UI/DPI、実GPU、実タッチ機器、実聴、本人PCは未確認。VFXの動画共有・負荷と結果画面の境界は各専用文書を参照する。

## 最終ローカル確認

標準47/47、native24/24段階、出場の専用10シナリオが成功。売却詳細から別人物へ変更した実OS24項目と、旧見積り遅延返信の専用19項目を追加確認した。独立静的レビューでは確定した阻害問題はなく、タッチ入力の局所座標がスクロール中に動く点を指摘。入力を固定座標へ揃え、連続2段階の模擬タッチで逆戻りを検出する回帰を追加した。これは実タッチ機器の検証とは区別する。
