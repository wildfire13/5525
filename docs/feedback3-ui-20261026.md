# 施設・受注・保存UIの追加調整

状態: ローカル実装・機能検証済み、原本照合・公開保留。基点は main `c37f9d2997e1113d5ed7443ed906d155b079e630`。原本資料の取得に接続障害があり、画像・図形・矢印を含む全シートとの照合は未完了。公開は照合完了または明示的な範囲変更まで保留する。

## 変更

- 共通ファイル選択でOSネイティブダイアログを要求する。対応しない環境ではGodotのフォールバックを使用。ネイティブ窓の表示寿命を追跡し、背後のキー入力と二重表示を防ぐ。既存JSON形式・初期保存先・ファイル名・原子的書込・上書き確認・読込前確認を保持する。サムネイルや保存形式の変更はない。
- 全施設NPCの上端を吹き出しより下げる。正規画像生成で通常（丸角と尾）、内心（雲と小円）、叫び（トゲ）の3図形を制作。文字は画像に焼き込まず別レイヤーで順に表示する。通常の施設台詞には通常形を使用し、他2形も独立描画可能。
- ギルドの両一覧のスクロールを保持し、控えと編成カードの入替、控えから下部顔列への追加・入替、顔列の順序変更にドラッグを接続。クリック操作と荷物所持者の警告・取消を保持。拒否されたドロップでは順序とスクロールを変えない。所属上限12と出場上限5を分離した既存仕様を維持する。
- 掲示板を左一覧／右詳細へ変更。既存の報酬、配達先、荷物1個、総重量値、依頼者、期限、依頼文を表示する。重量の新しい単位や内訳を推測しない。難易度と絞り込みは無効な予約領域だけで、新しい難易度制度・報酬を作らない。受注ボタン→人物画像でポーター選択→決定の2段階。選択や取消では荷物を付与せず、最後の確定だけで正規受注処理を実行。受注後は掲示板に留まり、右下の広場への移動を経て出発する。
- 宿屋は6列×最大2段。宿泊の正規処理で支払と対象全員の回復を一括確定し、その後、既採用ヒール素材を宿泊対象の全員へ共通開始時刻で表示し、数値表示だけをカウントアップする。元から満タンのHP/MPは増加表示を行わない。全員全快のクリックは無料の専用台詞のみ。連打、取消、退出、読込による古い確定を検査する。新しい状態異常は追加しない。

## 仕様判断

`native/campaign.js` の編成変更は人数・重複・候補を検査し、ポーター不在を許可する。ポーター必須は受注時だけの既存仕様であり、ギルド常時必須へ拡張しない。荷物個数は `native/quest-cargo.js` の1個発行契約に合わせる。未設定重量は未設定と表示する。

装備テンプレート、キャラクター作成、新報酬、新難易度制度、既存戦闘VFXの置換は対象外。

`python godot/tests/run_inventory_header_261020.py --evidence <リポジトリ外の検証先>` の標準チェックに、保存、吹き出し、ギルド、掲示板、宿屋の新回帰を登録。各プロファイルを隔離しBGM・ボイス・SEをOFFにする。

専用チェックは `native_file_dialog.gd`、`feedback3_speech_regression.gd`、`feedback3_guild_regression.gd`、`quest_board_feedback3.gd`、`inn_feedback3_regression.gd`。実OS操作とheadless結果を分離して記録する。現行候補は11人で、12人境界の合成検証を実在12人の試遊と混同しない。

Windows実ネイティブダイアログはユーザー確認待ち。LinuxでOSネイティブ機能が利用できない場合はフォールバックと保存ロジックの検証までとする。本人PCは操作しない。

## 同条件の負荷比較

基点と変更後を各3 fresh process、1920×1080・llvmpipe・音3種OFFで交互に測定。各画面48描画フレーム、再表示4回。フレーム間隔中央値の3実行中央値は、掲示板28.119→23.898ms、宿屋28.539→26.032ms、ギルド29.392→27.966ms。この標本では描画間隔の悪化は観測しなかった。画面ごとの常駐メモリ中央値は約7.7〜29.8MiB増加。全6processで再表示後のnode/resource増加とorphanはなく、正規保存状態も不変。実GPUや長時間の性能保証とは分離する。起動中央値は2161→2313msで、標本数とソフトウェア描画による変動を含む。

最終import/parseはエラーなし。今回の変更はローカルコミットまでとし、原本照合または明示的な範囲変更までpushと今回SHAのCIを実行しない。
