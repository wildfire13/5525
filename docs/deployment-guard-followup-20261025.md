# 配置開始操作と防御輪郭の追補

基点は実験ブランチの `41b62d1794580ac82354cbee138b9ee58b041e91`。同ブランチ内のローカル修正であり、main統合・push・ユーザーPC反映は今回含めない。別途制作中のアイコンは含めない。

## 配置画面の開始操作

新規プロフィールから「広場→地図→東へ出発→川沿い→配置」と進んだ時、1180×812では敵情報パネルが戦闘開始ボタンの92.7%を覆い、中央クリックでは開始できなかった。1283×832でも中央が覆われる。1920×1080の初期表示は開始できるが、そのまま縮小すると重なる。導入時期はこの検証では特定していない。

`battle_hud.gd` のパネル制限は戦闘中の履歴・順番詳細に下部領域を予約していた一方、配置中は予約がゼロだった。配置の陣形・開始操作を先に配置し、その画面上端に8pxの余白を加えた境界までを情報パネルの利用可能領域とした。共通メニューも開始ボタンの右下角へ重なっていたため、右の操作欄だけを必要な内容高に詰め、その下端をメニューの上8pxへ収めて開始ボタン全体を露出させる。陣形欄は元の位置を維持し、通常サイズの最下段マスを新しく隠さない。戦闘中は従来の下部操作の保護を維持する。ドラッグ・サイズ変更・保存位置の復元も同じ既存の制限処理を使う。

編成規則・配置マス・出発条件・開始処理・セーブ形式は変えない。中央クリックとTab/Enterのどちらでも開始でき、パネル操作後も開始操作を見失わないことを受入条件とする。

## 防御の輪郭

従来の盾形は地面上の選択リングとHP帯に近く、同時表示で読み分けにくかった。`skill_effect_layer.gd` の盾だけをカメラへ向く五角形の輪郭とし、選択リングの上へ離す。明るい青白い線と暗い細縁を用い、塗りは加えない。サイズを22〜30pxの高さへ収め、小さい盤面や角度変更時も形を保つ。

防御姿勢・実被害者の既存フラグを表す意味は変えない。軽減額・成功率を推測せず、発動判定・実被害者・乱数・表示時間0.42秒・他の演出を変更しない。HP・数値を描く既存レイヤーを上に保つ。新しい画像・音声・ノード・待ち時間は追加しない。

## 検証入口

```sh
python3 godot/tests/run_inventory_header_261020.py --evidence /tmp/5525-followup
python3 native/check.py
DISPLAY=:90 python3 godot/tests/run_facility_gui_261022.py --script deployment_start_gui --evidence /tmp/5525-deployment-gui
DISPLAY=:91 python3 godot/tests/run_facility_gui_261022.py --script guard_feedback_gui --evidence /tmp/5525-guard-gui
```

各出力先は新規でcheckout外、GUIには利用可能な隔離X11が必要。新規プロフィールの通常導線はfixtureで置き換えない。ゲーム用の本番セーブを使用せず、音声はOFF/Dummyとする。

`deployment_start_regression.gd` は通常導線・縮小／拡大／復帰・配置と戦闘の下部保護を照合する。`deployment_start_gui.gd` は実OSの中央クリック、Tab/Enter、合法な配置ドラッグ、情報パネル移動、履歴と順番詳細を検証し、画像と重なり矩形を保存する。

`guard_visibility_regression.gd` は3画面サイズ・3角度・3傾斜・3ズーム・3マスで、暗縁を含む盾が選択円／HP防御文字域へ重ならないことと終了時の消去を確認する。`guard_feedback_gui.gd` は3方向・画面幅と実際の防御／防御中被弾／肩代わり先を再生し、確定値・消失・音声OFFを照合する。

通常1180×812・1283×832・1920×1080では、味方の配置25マスの中心が固定操作欄に隠れないことも照合する。960×540の初期カメラでは最下段5マスが陣形欄にかかる。基点と修正後で座標が完全一致する既存制約であり、今回すべての小画面で全マスを初期表示できるよう修正したとは扱わない。既存のホイール縮小でzoom16.5から24へ変更すると、960×540でも全25マスの中心が固定操作欄に隠れず画面内へ収まることを実OS入力で確認した。カメラを自動で変更する処理は追加していない。

最終コードの標準回帰は36/36、nativeは23/23。初回の並行描画中に既存の0.12秒移動途中判定が一度失敗したため、期待値を変えず描画試験終了後に全36本を単独で再実行し成功した。

通常導線の最終補助試験は585/585、実OSは3サイズ各321/321、計963/963。防御の実OSは69/69、幾何回帰979/979、960×540の実ホイール補助確認は115/115。独立検証は通常サイズで全25マス非被覆を確認し、960初期カメラだけの既存被覆を基点と照合した。

防御の連続描画を1283×832・各180フレーム・新規プロファイル・他試験なしで比較した。フレーム中央値88.379→86.386ms、p95は100.283→100.654ms、node数451で不変、静的メモリは7514bytes増。ソフトウェア描画の測定であり、高速化やユーザーPCのFPSを保証するものではない。

Windows実画面・OS DPI、音声実聴、本人PCでの修正後プレイは未確認。新しいコミットのpush・CI・独立再確認は次段階に分ける。
