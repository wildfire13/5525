# 施設の吹き出しと話者の対応

通常の吹き出しの尾が右下の無人方向を示していたため、表示中のNPCの口元へ向ける。内心の小円も同じ話者へつなぎ、叫びの形には尾を追加しない。

## 実装

- 既存7枚のNPC画像に口元の画像座標を定義し、実際の人物表示矩形から画面上の口元を求める。人物画像・配置・選択乱数は変更しない。
- 既存の生成済みatlasを変更せず、通常・内心の本体と話者を示す部分を描画時に分離する。本体は元画像上半分のUVと上下対称のUVで閉じる。通常の尾は元画像の局所UVを回転し、内心の小円は口元方向へ配置する。
- 通常の尾の接合部だけ、本文側へ入り込む元の黒縁を小さい描画shaderで抑える。元の紙地と外側の尾の輪郭を維持する。
- NPCを表示しない狭い画面では、通常・内心は尾や小円のない本体を使う。見えない話者の位置を創作しない。叫びは元画像のまま。
- 本文は独立Labelのまま、文字列・文字サイズ・本文矩形・文字送り・施設操作を維持する。

単純な左右反転だけでは、NPCによって尾の延長方向が口元を外れたため採用しなかった。矩形の尾切り出しで生じた余分な画像片や接合線も、実画像を見て修正した。

## 検証と反映範囲

7人の異なる姿勢、1920×1080・1180×812・960×540、通常・内心・叫びを対象に、話者への方向、顔と本文の非遮蔽、狭い画面の無尾表示を実画面で確認した。専用回帰は `godot/tests/speech_tail_regression.gd`、実OS入力と画面記録は `godot/tests/speech_tail_gui.gd`。既存の文字送りと保存データ不変の回帰も維持する。

今回の指示はローカル修正のみ。push・新規CI・本人PC操作は行わない。Windows実画面や実GPUの確認は含まない。

最終結果：既存speech回帰232/232、新しいtail回帰78/78。実Linux X11の7人×3幅×3形状は457/457、21回のOS入力・63画像、終了コード0、エラーとリークなし。別担当が最終の方向・接合・本文と顔の非遮蔽を独立実見。元atlasのSHA256は変更前と一致。試作中の単純反転・切片接合不備・試験のparse失敗は外部証跡に保持し、最終成功と区別した。
