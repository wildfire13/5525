# GoGo To Go — ゲームサイクル試作01

`index.html` をブラウザーで直接開く。サーバー不要。音声・進行セーブなし。プレイログのみ、必要なときにJSONで保存できます。

この `prototype/` フォルダ内に実行ファイル・仮当て画像・Three.js・検証ツールをまとめています。検証コマンドはこのフォルダを作業ディレクトリにして実行してください。

## 自動チェック

Node.js 22以上で、次の一コマンドを実行します。追加パッケージは不要です。

```sh
node tools/check.cjs
```

リポジトリ直下からは `node prototype/tools/check.cjs`。どの作業ディレクトリから呼んでも動きます。全チェックを最後まで実行し、全通過なら終了コード0、失敗なら1、引数の誤りは2を返します。各テストには60秒の上限があります。

JSON形式で結果を残す場合：

```sh
node tools/check.cjs --json > qa/check-report.json
```

通常実行はファイルを書きません。JSON結果にはNodeのバージョン・各チェックの成否/所要時間/出力・実ブラウザーQAが未実行であることを含みます。

### 自動で確認する範囲

- `src/*.js` の構文チェックと、既存の戦闘・旅程・編成・ポーター・配置ルール検証
- 部品/薬 × 休息あり/なしの4パターンで、実際の戦闘処理を使った二連戦・資源持ち越し・配達・満額/遅配報酬・二重実行防止
- 実際のHTML・app/cycleコードをNodeのDOMシミュレーションに読み込んだ、受注から再挑戦までのクリック配線
- 配置の移動/交換/復元、ポーター交換のプレビュー/取消/確定、敗北、期限警告の戻る/Esc/続行、休息、結果画面、再挑戦時の状態初期化
- 槌戦士の選択・位置指定スタンプの範囲確認/取消/確定・スナイプの射程＋1・戦士入り二連戦
- ログのスナップショット独立性、再挑戦の区切り、保持上限、JSON保存ボタンからBlob/ダウンロード要求までの配線

通常進行の敵編成は固定し、戦闘ロジックは省略せずに実行します。細かい失敗・境界条件には、明示した固定局面も使用します。これは動作回帰のためのテストで、勝率・楽しさ・バランスの良否を判定するものではありません。

### 自動チェックに含まれないもの

DOMシミュレーションは実ブラウザーではありません。CSSの見た目、画像の実ロード、WebGL描画、ネイティブのドラッグ/Esc/フォーカス動作、実際に保存されたダウンロードファイルは確認しません。クラウドでの今回の検証では、file/localhostへのブラウザーアクセス制限により実ブラウザーQAは未実行です。

既存の `node tools/qa-cycle.mjs` / `node tools/qa-browser.mjs` は、Windowsの所定パスのEdgeを使う別の実ブラウザーQAです。今回の標準コマンドからは起動しません。過去の `qa/*.json` / スクリーンショットも、今回のブラウザー検証結果ではありません。

新しい回帰テストは `tools/test-*.cjs` として追加すると、標準コマンドで自動的に拾われます。UIシミュレーションは `tools/helpers/dom-harness.cjs` に限定実装されているため、新しいブラウザーAPIを使うときは実ブラウザーでの確認も必要です。

## 槌戦士・スタンプと弓・スナイプ（2026-10-02）

### 試し方

1. `index.html` で依頼を受け、準備画面で現在の1人を外して「槌戦士（仮）」を選ぶ。候補は11人、上限5人・ポーター必須は従来どおり。
2. 戦闘前配置で槌戦士を前線へ置く。既存の共通10×5座標のままなので、自陣右端と敵陣左端は隣接する。槌戦士の通常移動は自陣内のみ。
3. 槌戦士の番に「スタンプ」を選び、本人に縦横で隣接する中心マスをクリック。青く示す3マスと対象を確認して「スタンプを確定」。取消ではMPも行動も消費しない。
4. 弓手は「スナイプ」で通常攻撃より1マス遠い敵を選べる。通常攻撃ボタンの射程は従来どおり3。

### 今回の仮仕様

- **スタンプ（仮名・仮範囲）**：選んだ隣接セルで上・下・左・右を決め、その先端を横断する3マスを攻撃する。右向きなら本人から `(1,-1), (1,0), (1,1)`、上向きなら `(-1,-1), (0,-1), (1,-1)`。盤面外だけを切り、左右の盤面間は通常の連続座標として扱う。行端で反対端へ回り込まない。
- 中心に敵がいなくても、味方がいても指定可能。範囲内の生存中の敵だけに通常威力を適用し、味方は巻き込まない。範囲全体が空でも確定可能で、空振りとしてMP1・一行動を消費する。移動はしない。
- 各命中は既存の陣形・防御・かばう処理を使用。基本威力倍率は1。数値調整・最終バランス決定は行っていない。
- **スナイプ**：弓手の旧「強撃」を置き換え。その一撃だけ `通常射程 + 1`、現在は3→4。MP1・一行動、通常威力。旧1.7倍ダメージは削除。持続バフではなく、通常攻撃の射程・威力は変えない。敵弓手にも同じ射程と威力を適用する。
- 敵の予告はセル固定のまま。スナイプの対象が退いたときは追尾しない。空振り時は従来の敵弓スキルと同じくMP消費なしで見送り、命中時にMP1を消費する。
- 槌戦士は1名、個体ID `warrior`。仮能力は既存盾役を流用し、HP180・攻撃26・AGI10・通常射程1・MP6。画像は既存の `warrior.png` を無加工で使用。
- 高STRの戦士による槌攻撃を試すための仮当て。STR・種族・装備条件・装備変更画面は未実装。完成形での槌は職・種族専用ではなく、条件を満たせば装備できる想定。今回の `weapon: "hammer"` → スタンプという接続は検証用で、完成形の習得・使用条件を確定するものではない。
- 初期編成、戦闘単体版の既定4対4、敵の8候補からの抽選は変更なし。戦士を試すにはゲームサイクル版の準備画面で選ぶ。

## プレイログ

ゲームサイクル版・戦闘単体版とも、画面上部の「プレイログを保存（JSON）」で、その時点の記録を手元へダウンロードできます。不具合が起きたら、画面を閉じる前に保存してください。

- 受注/編成/出発/道/期限確認と取消/配置/戦闘の行動・結果/休息/配達/再挑戦を記録
- 各記録に時刻、連番、プレイ番号、操作内容、旅程、HP/MP/位置、敵の編成と予告、直近の戦闘メッセージを保存
- 再挑戦ではゲームの状態を初期化し、ログには新しいプレイ番号を付けて前の記録を残す
- 最大600イベント、またはイベントJSONのUTF-8サイズ合計2MiBまで。古いものから除き、`retention.droppedEvents` に省略件数を残す（整形した出力ファイルの大きさとは異なります）
- タブを閉じる/再読み込みすると消去。サーバー送信・localStorage・自動ファイル書き込みなし。URL・ブラウザー情報・認証情報は収集しない
- 形式は `schemaVersion: 1`。`current` が保存時点の状態、`events` が保持中の操作履歴。進行セーブや自動リプレイの機能はありません

プレイログ機能自体はゲームの数値・報酬・AIを変更しません。2026-10-02のスキル変更は上の専用節を参照。

## 一件の配達を遊ぶ

### 戦闘前の配置

各区間の道を選ぶと敵の編成・位置を公開した配置画面へ進みます。上のキャラボタンで味方を選び、味方陣のマスをクリックして配置。味方がいれば交換。移動距離の制限はなく、配置中の時間・HP・MP消費もありません。戦闘不能者は配置できません。

味方キャラの画像をドラッグ＆ドロップしても配置・交換できます。敵陣や盤面外へ落とした場合は変更されません。クリック操作も引き続き使用可能です。

金枠で護送陣、青い面で通常攻撃射程、緑枠で奇襲可能な敵を確認できます。「初期配置に戻す」は味方の配置だけを戻し、敵は再抽選しません。「この配置で戦闘開始」を押すと敵の予告と行動順を初期化します。二戦目にも配置可能、消耗は持ち越し。検証：`node tools/test-deployment.cjs` と `node tools/qa-cycle.mjs`。

### ポーター追加・最大5人（2026-09-29時点の記録）

トワ／ハルのポーター2人を追加し、10人から最大5人を選択。初期編成は既存4ロール＋トワ。ポーター最低1人が受注・出発に必要で、**どちらか1人でも倒れればクエスト失敗**。

ポーターは攻撃コマンドなし。通常移動2以内の味方との入れ替えをプレビューして確定できる。陣形成立中にスキルで自分を選ぶと、MP1で次の本人の番まで攻撃＋75％・被害−35％（仮数値、2名使用しても倍率の重複なし）。HP110・MP6・AGI12。回復薬や防御も利用可能。

敵は戦闘4ロールからランダム抽選。5人は今回の試験上限で、完成形の規模は未確定。追加検証 `node tools/test-porter.cjs`。素材は `assets/characters/背景透過済み/` を参照。

### 編成・敵の抽選・納期警告（ポーター追加前の記録）

準備画面で8人から1〜4人を選択。同ロールは最大2人。ガロ／バルト（盾）、リノ／セナ（弓）、ミオ／ユイ（癒）、ニカ／ルカ（斥）。追加キャラは名前と個体ID以外、元キャラと同じ能力・画像。4人選択中は一人外してから追加する。HP・MPは個体別に持ち越す。

敵は戦闘開始ごとに8候補から重複なしで抽選し、ロール重複は最大2人。敵の人数は従来どおり近道3→4人、迂回2→3人。初期位置は職の定位置を優先し、重複時は残る配置枠へ。陣形はロールではなく指定3マスの占有で成立。

ルート選択・休息の実行前に、残りを最短で進んだ配達時刻を計算。期限超過なら見込み時刻・超過時間・減額を確認ダイアログで表示する。キャンセルで時間・状態は変化しない。期限ちょうどなら警告なし。

`node tools/test-party.cjs` で能力一致、全70通りの4人編成、個体別持ち越し、敵構成の抽選、期限予測を確認。`tools/qa-cycle.mjs` は編成UI・警告の取消／続行も検証。通し戦闘の回帰検証部分では敵抽選を固定している。

依頼選択 → 補給・配置 → 道を選択 → 戦闘 → 野営 → 道を選択 → 戦闘 → 配達 → 報酬・成長。

配達後は専用の「任務達成」場面で、依頼主の言葉と護送隊を表示。「報酬と成長を確認する」を押して結果へ進み、その後に再挑戦を選べる。達成画面の記録は `qa/cycle-completion.png`。

- 二件から一件のみ受注。選ばなかった仕事は別の運び屋へ。
- 薬は納期7時間・報酬180G、部品は10時間・150G。積載は依頼品＋補給2枠、上限8枠。
- 救護セット（薬3個）か魔力セット（薬1個・各人初期MP＋2）。配置は護送陣かニカを弓手の列へ移す切り込み配置。
- 各区間は近道2時間／迂回4時間。近道の敵は3→4人、迂回は2→3人。敵の基本能力は戦闘単体版と共通。敵の薬は初戦0、二戦目1個。
- 戦闘一回は行動数によらず1時間。HP・MP・薬を持ち越す。野営で一度だけ2時間休息しHP＋60・MP＋2、戦闘不能からも復帰。
- 納期内なら満額と経験値100でLv.2、遅配なら報酬65％と経験値60。全滅時は撤退。
- 配達結果で終了。成長の持ち越し・連続受注・セーブ・統合は今後。奇襲は道中では第1段階（前方）、成長画面で第2段階（左右）を解放。第3段階（十字）は構想のみ。

### Three.js

`vendor/three/three.min.js` に Three.js 0.160.1 とMITライセンスを同梱。直接ファイル起動が可能な従来形式を使用し、実行時のCDN接続は不要。`src/world.js` が立体街道・光源・影・荷車と、戦闘の被弾／回復パーティクルを描画。戦闘の操作盤は既存DOMを使用し、ルールと描画を分離。

## 位置とスカウト

所属と現在の陣地は独立。内部では横10×縦5の共通座標を使い、2枚の盤面に描画する。射程は縦横距離。通常移動は経路長2以内。他ユニットを通り抜けない。

スカウトは両陣地へ移動できる。他職は自陣のみ。敵陣へ入った味方も、味方の回復・かばうの対象になる。

奇襲は同じ横列の左右どちらの敵へも直進し、その手前で止まって攻撃する。上下・斜めは対象外。途中に別の生存キャラがいれば使用不可で、迂回しない。距離の上限は設けず、通常威力の攻撃まで一行動・MP1。隣接済みでも使用可能。着地点は固定で、仮表示して確定／キャンセルできる。敵スカウトも同じ条件。

敵の予告はセル固定。奇襲の移動先が塞がれたら不発。移動可能でも対象が退いたら空振り（移動とMP消費は発生）。生存者のいるセルには重ならない。

## 操作

通常移動は仮選択 → 攻撃／スキル射程・陣形変化・着地点への予告を確認 → 確定／キャンセル。確定まで戦闘状態は変わらない。通常移動後の攻撃は次の本人の番。

行動順は味方が青、敵が赤。所属表示は侵入後も維持。上部に直前の敵行動を表示。
