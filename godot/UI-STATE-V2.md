# 状態別UI v2

基準コミット: `0afa5921416ce3e10d80aceb9fd65a56e2bf49f3`。
購入、戦闘、仲間の判断と実行を独立した表示状態に分ける。800×600以上に対応し、幅1120未満または高さ720未満では購入一覧と比較を切り替え、戦闘の判断枠を盤面下へ移す。

## 状態と責任

- `shop_view.gd`: S0〜S8。可視商品と次行の正規見積を直列取得し、最新の人物・部位・商品・進行世代だけ採用する。比較、全説明、取引確認、処理中、完了、失敗、木人試用を分離する。
- 購入は送信前にS5へ移り、応答の装備と所持金を照合してS6へ進む。0Gの異商品と負の差額も正規条件どおり扱う。応答不明はS7に留め、自動再送・人物変更による再購入を止める。別プロセスの状態を旧取引の成功証拠にしない。
- `battle_hud.gd`: B0〜B6とB2R。移動仮置き、読取専用の射程参考、対象指定、予測、既存演出と実結果を分離する。予測の世代が変われば破棄し、手番終了後は行動一覧へ戻す。
- `party_view.gd`: P0〜P2。人物選択、装備／能力・成長／スキル・効果の3タブ、8枠の読取専用詳細。両手装備の左手占有を明示し、同じ町の店だけ人物・部位を渡す。自由付替や予備装備管理は追加しない。
- `ui_dialog.gd`と`ui_memory.gd`: 排他的詳細窓、取消初期フォーカス、文脈・接続世代を確認したスクロール復元。

ゲーム規則、保存形式、画像・音声素材は変更しない。`Campaign.view`に既存装備とスキル説明の表示用メタデータを追加するだけで、UI状態は進行セーブへ保存しない。

## 確認

`python godot/check.py --godot <Godot 4.6 console executable> --full`

既存15段階に`ui_state_v2.gd`、`ui_state_v2_transactions.gd`、`review_async_regression.gd`、`review_layout_regression.gd`を加えた19段階。新しい購入完了画面・行動一覧の契約に従い、既存UI試験の表示期待を更新している。ゲーム状態・購入金額・画像・順次演出・保存の検証は維持する。

`tests/v2_bridge_probe.gd`は試験専用の遅延／応答断注入であり、製品シーンには接続しない。試験時のAPPDATA、LOCALAPPDATA、TEMPは必ず隔離する。

旧`tests/uiux_acceptance.gd`は旧UIの手動受入補助で、v2の合否根拠には使わない。旧65項目とv2の54項目は別の受入票で管理する。

自動試験はOS実入力や視認性の代用ではない。OS150%表示と独立した初見操作評価は別途行う。

## 独立レビューの遅延応答修正

古い見積は失敗応答も世代・商品一致を検査し、取消や新しい要求を上書きしない。接続全体の喪失は別に通知する。射程参考のawait後は窓・本文の生存、窓の同一性、進行／予測／接続世代を確認する。

`review_async_regression.gd`は実Node応答を保留し、取消・再選択・人物ABA、参考の閉じる／Esc／開き直し／新規開始／別セーブ読込を再現する。標準check.pyは終了コードに加えSCRIPT ERROR等のログも失敗として扱う。商品選択はラベル・枠・背景で持続表示し、パッシブ増減の正規説明を比較と最終確認にも表示する。

## 独立レビューの配置修正

小画面では上部・行動順・判断枠の重複を詰め、固定予告と44px以上の確認操作を維持する。戦闘用3視点は盤面を中心に収め、低視点は小画面でのみ少し上げる。小さい盤面ではビルボード面の投影寸法に従ってキャラとHPバーを縮尺調整し、味方は丸・敵は三角の足元表示で識別する。床マスのクリック判定と独立比較デモは変更しない。描画用の寸法はカメラ変更時に計算して保持する。

仲間は編成順の5人を先に、控えを別に表示する。標準幅では詳細を広く取り、小画面では編成5人の顔・名前・役割・HP/MPを一列で常時表示し、控えは別セレクタで閲覧する。装備の空欄は枠名を繰り返さず「なし」とする。

商店は対象者の小さな肖像を比較中と最終確認にも表示する（独立レビュー後の承認済み要件改訂）。標準幅の商品欄は360pxを基本とし、短い商品は約65pxの2行表示、長い条件は行が伸びて全文を保持する。

`review_layout_regression.gd`は5サイズの人物・商品配置、実Camera3Dによる800×600の3視点・行動選択・移動仮置き・単体／複数対象の座標変換と固定操作を確認する。投影値やControl矩形の検査は実画面の視認性合格を意味しない。

音楽試験の終了処理は固定150ms待ちから既存`finish_audio()`の解放確認へ変更し、AudioServerによるWAV解放完了を検査する。音楽の製品実装と素材は変更しない。
